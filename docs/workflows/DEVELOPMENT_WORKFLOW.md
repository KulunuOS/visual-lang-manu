# Development Workflow

1. Update `docs/project/PROJECT_BRIEF.md` when project scope changes.
2. Add or update tests before changing shared behavior when practical.
3. Keep reusable implementation in `src/visual_grasp_manu/`.
4. Keep scripts thin and task-specific.
5. Write generated outputs under `outputs/`.
6. Update `docs/project/CURRENT_STATE.md` after meaningful changes.
7. Review staged changes for public-safety before committing.

For experiments, record:

- command,
- dataset or asset version,
- configuration,
- metrics,
- known limitations,
- whether results are public-safe.
